# v4 直接注入验证记录

2026-10-30，Windows 11 build 26100，150% / 144 DPI。使用原生 Win32 API、线程 Hook 和屏幕复制，未使用 Computer Use。

## 实现结论

完成通用注入基础设施和插件接口：管理员入口、同用户完整性检查、x64/x86 辅助进程分发、目标 GUI 线程加载、只读 Probe、进程内布局修改、显式撤销和双层退出还原。Qt 插件与独立 SDK 示例使用同一 C ABI，新增适配器不需要修改注入内核。

当前构建不链接 adaptive.cpp，没有位置跟随逻辑。Qt Widgets 使用原 backing store，Quick 使用原场景图，均不创建新的原生 HWND。保留的 250ms / 750ms 定时器仅检查控制器/守护进程是否存活。

**尚未完成所有第三方软件适配。** Qt 示例证明原布局修改可行，不代表已经支持 Edge、QQ、Visual Studio 或任意 Qt 应用。

## 功能回归

- x64 CTest 10 项通过，包括独立 DLL 接口、严格默认策略、Qt 原布局、历史 Win32/Qt/WPF 回归。历史扩展路径的测试通过不代表默认路径会使用它。
- Win32 的 5 项均通过。曾与 x64 桌面动画测试重叠运行导致旧跨进程状态测试失败，停止重叠后单独重跑该项通过；保留日志，没有把首次失败抹掉。
- 完整包管理员 UI / CLI 11 项通过：启动、样例按钮、两种 Qt 自动接管、同一控制器接管 x64/x86、暂停全部还原、CLI 注入 x86、核实辅助进程路径、期限撤销、恢复和控制器异常还原。结果在 `out/controller-direct-v4/checks.json`。
- Qt 测试检查原标签输入、首次客户区/外框、隐藏原按钮、24 次连续移动缩放、最小化/最大化/恢复、红按钮关闭、撤销后 QML 绑定继续随尺寸变化、控制器故障和守护进程故障还原。测试仅关闭自建应用。
- 该次 24 次同步移动缩放加诊断调用最大耗时：Quick 约 47ms，Widgets 约 16ms；这是本机端到端样本，不能解释为所有程序的延迟承诺。架构中没有等待跟随窗口的轮询周期。

## 可用范围与后续适配

目前 Qt 插件严格限定 6.11.1 x64、Core/Widgets/Quick 三个模块已加载、顶端指定 TabBar 布局及原按钮命名；使用私有 QML 绑定保存接口，因此强制精确版本匹配。x86 包目前仅原生路径。

后续接入 Chromium/CEF/Electron 需要对应运行时的 Views 布局适配器；WPF 需要实际托管视觉树布局适配。不能通过统一修改 WS_CAPTION、WM_NCCALCSIZE 或加载任意 DLL 自动完成所有内部布局。未适配窗口保持跳过，不回退到跟随/覆盖层。
