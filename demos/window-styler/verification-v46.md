## WinUI 原生对照复现了历史三个差异像素

自有标准 TextBox 的 Debug 固定 fixture SHA256 仍为 `03769E86CA85899C5A9836757B5EE592900FF340976FEA837F322F395BDB8D0F`。r5 的三个独立、从未注入的事先对照中，前两个最终整窗 PNG 为 `78153854F6745115B632E59EE7A6CE5CBCF8C6B3EA83CF013F7A49A7542249B3`，第三个为 `60D1D5EF3C2B86CA8ADB5BF4DEC17511FDB2A60C2C9AA99E9F74E3BE14610BE6`。原生对照的编辑/选区/undo/redo/焦点/Loaded/几何状态相同。这两个哈希分别与 v44 历史失败目标和当时原生对照逐字一致。

解码完整 PNG 后，仅三个 BGRA 像素不同，位置和值也与历史失败完全相同：

```text
243,259: 2E-2E-2E-FF -> 2F-2F-2F-FF
242,260: 2F-2F-2F-FF -> 30-30-30-FF
242,490: 30-30-30-FF -> 31-31-31-FF
```

因此，这个像素变体在没有注入时也能出现。底层渲染产生变体的机制尚未定位；v44 的失败仍按原结果保留。本轮没有增加像素容差、裁剪、遮罩、失败后生成参考，或反复采集直到匹配。现有断言仍要求目标完整整窗文件严格匹配本场景事先生成的一个独立原生对照。r5 单场景通过 224 项；后续 r6 的 Debug 深浅色、正常撤销及控制器异常退出完整矩阵通过 896 项。Release r6 完成深色两个场景后，在浅色目标的输入前检测到前台变为 ChatGPT，保护中止，整组未计通过。

私有证据：`out/live-v46/text-Debug-dark-r5`、`text-Debug-all-r6`、`text-Release-all-r6`、`native-three-pixels-r7.json` 和对应完整差异文本。较早的后台 WGC 诊断 r61 也得到深浅色各两组原生对照与正式模块恢复后的首帧一致，但它不替代上述真实输入与屏幕截图检查。

Release 的剩余浅色正常/异常退出场景 r23、r24 分别通过 224 项，含新增前台时间轨迹。结合 r6 中已完成的深色两个场景，Release 四场景各 224 项，合计 896 项；中止的 r6 整组仍保留为失败。Debug 和 Release 的固定二进制、三个事先独立原生对照、真实输入及完整 PNG 严格匹配规则均未改变。

## 前台验证器的启动与保护

Windows 拒绝首轮 SetForegroundWindow 时，验证器在发送键盘事件前即拒绝继续。新增激活入口只允许经 PID、fixture 私有属性、原生 HTCAPTION 命中、精确物理鼠标位置和遮挡检查确认的自有未注入窗口接收一次标题栏点击；用户按住修饰键或鼠标按钮时拒绝执行。键盘、三灯和截图原有前台/遮挡检查继续生效。

r3/r4 在第三个窗口启动时发现上一个自有置顶截图背景窗挡住激活点。现每个独立窗口开始前销毁该背景窗，结束时仍恢复鼠标和先前前台。原失败保留。新增可选 `-ForegroundTrace` 只记录检查点、窗口/PID、系统 tick 和最后输入时间，用于区分后续前台转移；不记录用户键盘内容或窗口文字。
